# Debian/Ubuntu Server Provisioner

Автоматизированный Bash-скрипт для первичной настройки, создания безопасного пользователя и комплексной защиты (Hardening) чистых серверов на базе Debian / Ubuntu.

---

## Алгоритм работы скрипта

### === Подготовка к запуску ===
1. **Проверка прав:** Проверяется, запущен ли скрипт от имени `root` (через `sudo`).
2. **Тихий режим:** Отключаем любые интерактивные диалоговые окна `dpkg` и `apt`, чтобы скрипт не зависал при запросах.
3. **Конфигурация:** Задаём глобальные переменные (`NEW_USER`, `SSH_PUB_KEY`).

---

### [1/6] Обновление системы и установка пакетов
1. **Обновление и установка софта:** Скачивание свежих списков пакетов и установка базовых утилит (`curl`, `git`, `htop`, `ufw`, `fail2ban`, `unattended-upgrades`).
2. **Часовой пояс:** Принудительная установка системного времени в **UTC** для синхронизации логов.

---

### [2/6] Настройка нового пользователя и SSH-ключей
1. **Новый пользователь:** Создаём изолированного пользователя `devops` с домашней директорией и оболочкой `/bin/bash`.
2. **Права Sudo:** Добавляем пользователя в группу `sudo`.
3. **Беспарольный Sudo:** Настраиваем файл в `/etc/sudoers.d/` с правилом `NOPASSWD:ALL` для удобства автоматизации.
4. **Директория SSH:** Создаём папку `.ssh` и выставляем строгие права `700` (доступ только владельцу).
5. **Публичный ключ:** Записываем публичный SSH-ключ (`Ed25519`) в файл `authorized_keys` с правами `600`.
6. **Владение:** Передаём права на папку `.ssh` созданному пользователю (`chown`).

---

### [3/6] Защита SSH-сервера (Hardening SSH)
1. **Защита от блокировки:** Проверяем, что файл `authorized_keys` не пустой (защита от потери доступа к серверу).
2. **Изолированный конфиг:** Создаём файл `/etc/ssh/sshd_config.d/99-hardening.conf`:
   - Отключаем вход под `root` (`PermitRootLogin no`).
   - Отключаем авторизацию по паролям (`PasswordAuthentication no`).
   - Оставляем только SSH-ключи (`PubkeyAuthentication yes`).
3. **Валидация синтаксиса:** Проверяем корректность конфига через `sshd -t` перед мягким перезапуском службы (`systemctl reload ssh`).

---

### [4/6] Настройка Firewall (UFW)
1. **Политика по умолчанию:** Задаём жесткую политику **Default Deny Incoming** (заблокировать всё входящее) и **Default Allow Outgoing**.
2. **Открытие портов:** Разрешаем только необходимые сервисы: `22/tcp` (SSH), `80/tcp` (HTTP), `443/tcp` (HTTPS).
3. **Активация:** Включаем фаервол в неинтерактивном режиме (`ufw --force enable`).

---

### [5/6] Настройка защиты от брутфорса (Fail2Ban)
1. **Конфигурация:** Создаём файл `/etc/fail2ban/jail.local` с правилами бана за 3 неудачные попытки входа в течение 10 минут (бан на 1 час через UFW).
2. **Перезапуск:** Применяем настройки и перезапускаем службу `fail2ban`.

---

### [6/6] Настройка автоматических обновлений безопасности
1. **Авто-патчи:** Включаем тихую фоновую установку критических патчей безопасности через `unattended-upgrades`.

---

## Как запустить?

```bash
# 1. Скачать скрипт на сервер
scp ./setup.sh devops@YOUR_SERVER_IP:~/

# 2. Подключиться по SSH
ssh devops@YOUR_SERVER_IP

# 3. Сделать файл исполняемым и запустить
chmod +x setup.sh
sudo ./setup.sh
```
